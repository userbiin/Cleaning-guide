# Organization Object Detector v2 — Detect → Describe → Organize

> v1 baseline은 "물건의 **이름**"만 탐지했다. v2의 목표는 Florence-2 같은 **describe 모델**을 붙여
> "물건의 **상태/속성**(빈 페트병, 엉킨 케이블, 다 쓴 휴지)"까지 파악하고, 이를 근거로 LLM이
> **더 정확한 정리 판단(버릴 것 / 옮길 것 / 제자리)** 을 내리게 만드는 것이다.
> 최종 산출물은 **FastAPI 백엔드 + iOS(SwiftUI) 시연 앱**이다.

이 문서는 Claude Code가 v1 baseline(`baseline.py`)을 v2 시스템으로 발전시키기 위한 구현 명세서다.

---

## 0. 한 줄 요약 (왜 v2인가)

| 구분 | v1 (현재) | v2 (목표) |
|---|---|---|
| 탐지 출력 | `bottle`, `cup` (라벨만) | `bottle` + `"a crumpled empty plastic bottle"` (라벨 + 속성 서술) |
| 정리 판단 근거 | 카테고리 규칙만 | 카테고리 + **describe 속성** |

| 평가 | 정성적 | **describe 유무 A/B 비교 + 정리 판단 정확도** |

## 1. 연구 주제(Thesis) — 평가 설계의 뼈대

> 교수님 피드백: "성능을 어떻게 비교할지, 모델 한계에 초점을 맞춰 해결할지 / 상업적 측면에서 판단 정확도를 높일지 정해라."

→ **측정 가능한 가설 하나**를 메인으로 고정한다. v2는 아래 **B를 메인**, A를 보조 근거로 사용한다.

### 메인 가설 (B · 실용 정확도형)
> "객체 탐지 결과에 **describe 속성 정보**를 추가하면, LLM이 생성하는 정리 판단
> (버릴 것 / 옮길 것 / 제자리)의 **정확도가 유의미하게 향상된다.**"

- **독립변수**: describe 모델 사용 여부 (off / on)
- **종속변수**: 정리 판단 정확도 (Organization Decision Accuracy)
- **실험 형태**: 동일 이미지 50장에 대해 `Baseline(라벨만)` vs `Proposed(라벨+describe)` A/B 비교

### 보조 근거 (A · 한계 해결형)
- v1 baseline의 알려진 한계: 낮은 conf threshold(0.08)로 인한 **중복/오탐**, 겹친 물건(occlusion), 케이블·립밤 등 **소형 객체 누락**.
- describe 정보와 SAM 2 segmentation으로 이 한계들을 일부 보완 → Small Object Recall / Occlusion 지표로 별도 측정.

### 비교 대상 모델 (3-way)
| 이름 | 구성 | 역할 |
|---|---|---|
| **Baseline** | YOLO-World, 라벨만 | 대조군 (v1) |
| **Proposed-A** | YOLO-World/YOLOE 박스 → Florence-2가 박스별 describe | 탐지·서술 분리형 |
| **Proposed-B** | Florence-2 `<DENSE_REGION_CAPTION>` 단독 (탐지+서술 통합) | 단일 모델형 |

> A vs B 비교 자체가 "describe 모델을 어떻게 붙이는 게 나은가"라는 논문 contribution이 된다.

## 3. Describe 모델: Florence-2 통합

### 3.1 왜 Florence-2인가
- Microsoft, **MIT 라이선스**, 0.2B(base)/0.7B(large)로 가벼움 → 백엔드 탑재 부담 적음.
- 단일 모델로 detection / dense region captioning / segmentation / OCR 지원.
- task prompt 기반: 같은 모델에 프롬프트만 바꿔 여러 모드 사용.

| Florence-2 task prompt | 출력 | v2에서의 용도 |
|---|---|---|
| `<OD>` | bbox + label | (대조용) 통합 탐지 |
| `<DENSE_REGION_CAPTION>` | bbox + **서술형 라벨** | **Proposed-B 핵심** |
| `<REGION_TO_DESCRIPTION>` | (박스 입력) → 서술 | **Proposed-A 핵심** (YOLO 박스 설명) |
| `<REGION_TO_CATEGORY>` | (박스 입력) → 카테고리명 | 카테고리 보조 |
| `<CAPTION_TO_PHRASE_GROUNDING>` | (텍스트 입력) → bbox | 특정 물건 찾기 |

> ⚠️ 구현 전 Hugging Face `microsoft/Florence-2-large` 모델 카드에서 region 입력 토큰 포맷
> (location token, 1000-bin 좌표 인코딩)을 반드시 확인할 것. 모델은 float16으로 로드한다.

### 3.2 Florence-2 래퍼 (신규 파일: `models/describer.py`)
```python
# 의존성: transformers, torch, einops, timm
from transformers import AutoProcessor, AutoModelForCausalLM
from PIL import Image
import torch

class Florence2Describer:
    def __init__(self, model_id="microsoft/Florence-2-large", device=None):
        self.device = device or ("cuda" if torch.cuda.is_available() else "cpu")
        self.dtype = torch.float16 if self.device == "cuda" else torch.float32
        self.model = AutoModelForCausalLM.from_pretrained(
            model_id, torch_dtype=self.dtype, trust_remote_code=True
        ).to(self.device)
        self.processor = AutoProcessor.from_pretrained(model_id, trust_remote_code=True)

    def _run(self, image: Image.Image, task_prompt: str, text_input: str = None):
        prompt = task_prompt if text_input is None else task_prompt + text_input
        inputs = self.processor(text=prompt, images=image, return_tensors="pt").to(self.device, self.dtype)
        generated = self.model.generate(
            input_ids=inputs["input_ids"],
            pixel_values=inputs["pixel_values"],
            max_new_tokens=1024, num_beams=3, do_sample=False,
        )
        text = self.processor.batch_decode(generated, skip_special_tokens=False)[0]
        return self.processor.post_process_generation(
            text, task=task_prompt, image_size=(image.width, image.height)
        )

    # Proposed-B: 탐지 + 서술 통합
    def dense_region_caption(self, image: Image.Image):
        return self._run(image, "<DENSE_REGION_CAPTION>")
        # 반환: {"<DENSE_REGION_CAPTION>": {"bboxes": [...], "labels": ["a half-open notebook", ...]}}

    # Proposed-A: YOLO가 준 박스 하나를 서술 (region 입력 포맷은 모델 카드 확인 필수)
    def describe_region(self, image: Image.Image, bbox_xyxy):
        # TODO: bbox를 location token 시퀀스로 변환해 text_input으로 전달
        return self._run(image, "<REGION_TO_DESCRIPTION>", text_input=region_tokens)
```

### 3.3 Attribute 파싱 (신규 파일: `pipeline/attributes.py`)
describe 문자열에서 정리 판단에 쓰일 **상태 신호**를 규칙/키워드로 추출한다.
```python
STATE_KEYWORDS = {
    "trash_signal": ["empty", "crumpled", "used", "torn", "wrapper", "trash"],
    "needs_wash":   ["dirty", "stained", "half-full", "leftover"],
    "tidy_target":  ["stacked", "folded", "closed"],
}
# describe="a crumpled empty plastic bottle" → trash_signal=True → LLM에 "버릴 것 후보"로 표시
```
이 상태 신호를 LLM 프롬프트에 추가하는 것이 **메인 가설 B의 처치(treatment)** 다.

## 4. 평가 프레임워크 (신규 디렉터리: `eval/`)

### 4.1 데이터: 직접 수집 50장
- 책상/책꽂이/옷장/화장대 등 실제 어질러진 공간 사진 50장.
- 각 사진의 ground truth를 **사람이 직접 라벨링**:
  - 객체 bbox (Recall 측정용)
  - 각 객체의 정답 정리 판단: `discard`(버릴) / `relocate`(옮길) / `keep`(제자리)

### 4.2 핵심 지표
| 지표 | 의미 | 메인 가설 관련 |
|---|---|---|
| **Organization Decision Accuracy** | 시스템 판단 vs 사람 정답 일치율 | ★ B 메인 지표 |
| Category Accuracy | 카테고리 분류 정확도 | 보조 |
| Detection Recall | 실제 물건 중 탐지 비율 | A 보조 |
| Small Object Recall | 케이블/립밤 등 소형 객체 Recall | A 보조 |
| False Positive Rate | 오탐 비율 (v1 conf=0.08 약점) | A 보조 |
| Latency (p50/p95) | 1장 처리 시간 | 앱 시연 실용성 |

### 4.3 A/B 실험 스크립트 (`eval/run_ab.py`)
```text
for each image in dataset(50):
    result_baseline = pipeline(image, describe=OFF)   # 라벨만 → LLM
    result_proposed = pipeline(image, describe=ON)    # 라벨+describe → LLM
    score_both_against(ground_truth)
출력: 두 조건의 Organization Decision Accuracy 평균 + 차이 + (가능하면) paired t-test
```
> 이 표 하나가 보고서의 핵심 결과 그림이 된다. "describe 추가 시 정확도 X%p 향상".

### 5.3 v1 → v2 코드 이식 메모
- `baseline.py`의 `CATEGORY_MAP`, `classify_item`, `build_llm_prompt`, `ask_openai_for_recommendation`는 거의 그대로 `pipeline/`으로 분리.

- LLM 프롬프트에 `description`/`state` 필드를 추가하는 것이 v2의 핵심 변경점.

## 7. 프론트엔드 (iOS · SwiftUI · Xcode)

백엔드는 순수 REST API이므로 Swift 쪽은 **사진 업로드 + JSON 렌더**만 담당한다.

### 7.1 최소 화면 구성
1. `PhotoPicker` / `Camera` → `UIImage` 획득
2. 업로드 진행 인디케이터
3. 결과 화면: 원본 이미지 위에 bbox 오버레이 + 객체 리스트(description, decision 배지) + 정리 가이드

### 7.2 업로드 스니펫 (참고용)
```swift
struct AnalyzeResponse: Codable {
    let summary: String
    let objects: [DetectedObject]
    let guide: Guide
    let annotatedImageUrl: String
    let latencyMs: Int
}

func analyze(image: UIImage) async throws -> AnalyzeResponse {
    guard let jpeg = image.jpegData(compressionQuality: 0.85) else { throw URLError(.badURL) }
    var req = URLRequest(url: URL(string: "http://<MAC_LOCAL_IP>:8000/analyze")!)
    req.httpMethod = "POST"
    let boundary = UUID().uuidString
    req.setValue("multipart/form-data; boundary=\(boundary)", forHTTPHeaderField: "Content-Type")

    var body = Data()
    body.append("--\(boundary)\r\n".data(using: .utf8)!)
    body.append("Content-Disposition: form-data; name=\"image\"; filename=\"photo.jpg\"\r\n".data(using: .utf8)!)
    body.append("Content-Type: image/jpeg\r\n\r\n".data(using: .utf8)!)
    body.append(jpeg)
    body.append("\r\n--\(boundary)--\r\n".data(using: .utf8)!)
    req.httpBody = body

    let (data, _) = try await URLSession.shared.data(for: req)
    let decoder = JSONDecoder()
    decoder.keyDecodingStrategy = .convertFromSnakeCase   // snake_case → camelCase
    return try decoder.decode(AnalyzeResponse.self, from: data)
}
```

### 7.3 로컬 데모 주의사항
- 실기기 테스트 시 폰과 Mac이 같은 Wi-Fi여야 하고, URL은 `localhost`가 아니라 **Mac의 LAN IP**.
- iOS는 평문 HTTP를 막으므로 `Info.plist`의 App Transport Security에 로컬 IP 예외 추가(데모 한정).
- bbox 좌표는 백엔드가 처리한 이미지 해상도 기준 → 앱에서 표시 해상도에 맞게 **스케일링** 필요. (백엔드가 전처리 후 이미지 크기를 응답에 포함시키면 편함.)

## 9. Claude Code 즉시 작업 (이번 세션)

1. 위 **디렉터리 구조(5.2)** 스캐폴딩 생성.
2. `baseline.py`의 `CATEGORY_MAP`/`classify_item`/`build_llm_prompt`를 `pipeline/category.py`, `pipeline/llm.py`로 이식.
3. `models/detector.py`: 기존 YOLO-World 탐지를 **dict 리스트만 반환**하도록 리팩터링(시각화 분리).
4. `app/main.py` + `app/schemas.py`: `POST /analyze` 구현. **describe=False 경로부터** end-to-end로 통과시킬 것.
5. `models/describer.py`: Florence-2 래퍼(3.2) 구현. `<DENSE_REGION_CAPTION>` 먼저 동작 확인.
6. `pipeline/orchestrator.py`: detect→(describe)→attribute→category→LLM 연결. `describe` 플래그로 분기.
7. `pipeline/attributes.py`: describe → state 키워드 파싱(3.3).
8. `eval/run_ab.py` + `eval/metrics.py`: describe ON/OFF로 Organization Decision Accuracy 비교하는 스켈레톤.
9. `ios/`: SwiftUI 업로드/렌더 최소 앱 스캐폴딩(7장 스니펫 기반).
10. `requirements.txt` 작성.

> 구현 우선순위: **P1(describe 없이 도는 백엔드) → P2(Florence-2) → P5(A/B 실험)**.
> describe 없이 도는 baseline 경로를 먼저 통과시킨 뒤 describe를 얹어야 A/B 대조군이 깨지지 않는다.

## 10. 참고 모델/데이터 (v2 추가)

- **Florence-2** (Microsoft, MIT) — describe 핵심. dense region caption으로 속성 서술.
