> **LLM 정리 판단**(discard / relocate / keep + 가이드) → **iOS 앱 렌더**.

> **탐지/describe 모델의 성능(정확도)** 이고, LLM 정리 판단 A/B는 **응용 시연(보조)** 으로 내린다.
> (v1/v2에서 메인이던 "LLM decision A/B"가 보조로 강등됨)

## 1. 프로젝트 성격 & 연구 주제(Thesis)

**CV 수업 → 모델 탐지/서술 성능이 평가의 중심.** thesis는 "한계 해결형(A)"이 메인이다.

### 메인 thesis (A · CV 성능)
> "open-vocabulary detection + describe 모델을 cluttered 실내(책상/방) 도메인에 적용하고,
> **fine-tuning으로 탐지 정확도(특히 소형 객체)를 개선**한다. 모델의 한계(소형/occlusion/오탐)를
> 정량 지표로 측정하고 개선한다."

### 보조 thesis (B · 응용)
> "탐지 결과에 describe 속성을 추가하면 LLM 정리 판단이 개선된다." → 시연/부록 수준.

## 2. 평가 우선순위 (재정렬) + 지표

| 순위 | 평가 | 지표 | 비고 |
|---|---|---|---|
| **1 (CV 코어)** | 탐지 정확도 | **mAP@0.5, mAP@0.5:0.95**, Recall, Precision, **Small-object AP**, FP rate | GT bbox 대비, IoU 0.5 |
| **1 (CV 핵심 기여)** | **fine-tuning 전후 향상** | zero-shot → fine-tuned 위 지표 delta | 스트레치 아님, **코어** |
| 2 | detector 비교 | YOLO-World vs YOLOE vs fine-tuned | `compare_detectors.py` 활용 |
| 2 | describe 모델 품질 | Florence-2 서술 정확도 (표본 감사 + 95% CI) | vision-language CV 평가 |
| **3 (응용 시연)** | LLM decision A/B | decision accuracy, cost-weighted acc, discard recall | describe ON/OFF, **보조** |

> **즉 헤드라인 결과는 mAP/Recall 표와 "fine-tuning 전후 향상 표"**다. LLM A/B는 부록.
> `compare_detectors.py`는 이미 recall/precision/small_recall을 뽑으므로 **mAP 계산만 추가**하면 1순위 지표가 완성된다.

## 3. 데이터 전략

**원칙: 탐지 성능(A)은 공개 라벨 데이터로 물량 확보, decision 라벨(B)은 자체 사진에만.**

### 3.1 공개 데이터 (탐지/ fine-tune 용 — 직접 라벨 불필요, 박스 이미 있음)
- **LVIS** — 1,203 카테고리 long-tail. 가위·리모컨·병 등 **소형/다양 객체에 이 프로젝트에 가장 적합**. (FiftyOne으로 다운로드)
- **Roboflow Universe desk/clutter 셋** — "Detecting working desk"(~3,124장), "Office Desk"(~2,245장) 등. 품질 들쭉날쭉, prototype/fine-tune용. (Roboflow SDK)
- **⚠️ HomeObjects-3K 주의**: 클래스가 가구(bed/sofa/chair/table/lamp/tv/laptop/wardrobe/window/door/plant/photo frame) 12종이라 **책상 위 소형 잡동사니와 도메인이 다름**. 큰 가구/공간 맥락 외엔 소형 객체 평가에 부적합 → 메인 데이터로 쓰지 말 것.
- 소형 객체 recall 부족 시 **SAHI(이미지 슬라이싱 추론)** 적용 검토.

### 3.2 자체 수집 (도메인 매칭 + decision 라벨 — 필수, 사람이 직접)
- 폰으로 찍은 어질러진 책상/책꽂이/옷장/화장대 사진 **30~50장** (dev/test 분할).
- 공개 셋엔 "이 컵을 주방으로" 같은 정리 맥락이 없어 **decision 라벨은 자체 사진에만 의미** 있음.
- 분할: dev(모델선정·튜닝) / test(최종 평가, freeze). dev ∩ test = ∅.

> ※ 평가 사진은 사람이 직접 모아야 한다(자동 수집 불가). 탐지 지표 물량은 공개 셋으로, decision은 자체 사진으로 분담.

## 4. Ground Truth 포맷 (bbox + decision 한 파일)

`eval/ground_truth/<이미지stem>.json` 의 각 객체에 **`decision` 필드를 추가**한다. 새 파일 불필요.

```json
{
  "image_id": "test1",
  "objects": [
    {"label": "bottle", "bbox": [120,80,240,360], "decision": "discard"},
    {"label": "book",   "bbox": [300,50,520,200], "decision": "keep"},
    {"label": "cup",    "bbox": [40,400,120,480], "decision": "relocate"}
  ]
}
```
- **bbox+label** → 탐지 지표(A, 1순위)에 사용
- **decision** → LLM A/B(B, 3순위)에 사용. **자체 사진에만** 채움(공개 셋 GT엔 생략)
- attribution cascade가 IoU로 detected↔GT 매칭: 매칭된 객체는 decision 비교(B), 놓친 객체는 detection 실패(A)
- `EXAMPLE_FORMAT.json`도 `decision` 필드 포함하도록 업데이트할 것

**decision 라벨링은 "정답지 작성"이지 LLM 채점이 아니다.** 사람이 LLM 출력을 보기 전에, 사진 속 물건을 보고 올바른 판단(discard/relocate/keep, 오탐이면 invalid)을 매긴다. 이미지를 보면서 매긴다(위치 맥락 필요). 라벨러 2인 → Cohen's kappa.

## 6. Decision Taxonomy

- `discard` (버릴 것): 재사용 의도 없는 빈 용기·포장지·다 쓴 소모품
- `relocate` (옮길 것): 유효하지만 현재 위치가 부적절
- `keep` (제자리): 현재 위치가 적절/상시 사용
- `invalid`: 오탐(실제 물건 아님) → decision 정확도에서 제외

경계 규칙(`labeling_guide.md`에 명문화): 반쯤 남은 음료=relocate, 빈 캔=discard, 모호 시 keep.

## 7. LLM 프롬프트 ON/OFF (보조 실험 B용)

**공정성: OFF와 ON의 유일한 차이는 `description`+`state` 두 줄.** 나머지(instruction·형식·모델·temperature) 100% 동일.

공통 instruction:
```
너는 실내 정리 컨설턴트다. 탐지된 물건 각각에 discard/relocate/keep 중 하나를 판정하라.
- discard: 재사용 의도 없는 빈 용기·포장지·소모품
- relocate: 유효하나 위치가 부적절한 물건
- keep: 위치가 적절한 물건
확신이 낮으면 keep.
```
OFF 리스트: `- bottle (conf 0.71) ×1`
ON 리스트: 위 + `· description: "a crumpled empty plastic bottle"` / `· state: trash_signal`

출력(양쪽 동일, JSON 강제):
```json
{"decisions":[{"object_id":0,"label":"bottle","decision":"discard"}],
 "guide":{"priority_top3":["..."],"five_min_routine":["..."],"by_category":{}}}
```

**B 지표 보조: cost-weighted accuracy** (오류 비용 비대칭). 비가역 오류(멀쩡한 걸 버리라 함)에 최대 가중:
```text
              pred:discard  pred:relocate  pred:keep
gt:discard         0             2            3
gt:relocate        3             0            1
gt:keep            4             1            0
```
+ **false-discard rate**(안 버릴 걸 버리라 한 비율)도 보고. 가중치는 balanced/안전우선 2세트로 sensitivity 확인.

## 8. Florence-2 describe

- **기본**: `<DENSE_REGION_CAPTION>` → 박스+서술 1-pass, region token 변환 불필요.
- **대안(YOLO 박스 서술)**: 박스를 crop해서 `<MORE_DETAILED_CAPTION>` → token 변환 회피.
- 로드: `attn_implementation="sdpa"`, GPU float16 / Mac은 float32 fallback.
- describe 신뢰도 감사(2순위 지표): 평가 사진의 describe 출력만, 표본 100~150, state_signal 층화, 결정 뒤집는 서술 오버샘플, "정확도 X% (95% CI)" 보고.

## 10. 백엔드 / iOS (요약)

- **백엔드**: FastAPI `POST /analyze` (multipart). lifespan으로 모델 사전로드(cold start 대응). 응답에 `processed_image_size:[w,h]` 포함(bbox 스케일링용), `objects[]`(label/description/state/category/decision/confidence/bbox), `guide{}`, `latency_ms`. 입력 heic 지원(`pillow-heif`).
- **iOS(SwiftUI)**: 사진 업로드 → bbox 오버레이(백엔드 해상도→표시 해상도 `CGAffineTransform` 스케일링) + decision 배지 + 가이드. URLError/5xx 에러 처리 필수.
